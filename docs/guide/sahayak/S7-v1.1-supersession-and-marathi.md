# S7 — v1.1: "Which rule is in force?" + Marathi

**Goal:** (1) supersession awareness: the system knows which circulars amend or repeal which directions and, by default, answers from provisions currently in force, saying so; (2) Marathi: IndicQA-mr numbers and a small Maharashtra Government Resolution (GR) slice.
**Time:** ~12–15 h. Built after Gatekeeper v1.0.

## Part A — Supersession awareness

### Concept primer

> 📘 RBI regularly **consolidates** many circulars into a Master Direction and lists the circulars it repeals, and later **amends** Master Directions through new circulars ⚠️ (verify how this is stated in the documents you ingested: typically an annex or a paragraph listing the circulars consolidated/repealed, and "Updated as on <date>" headers). If the system answers from a repealed circular, the answer is confidently wrong: the worst kind of wrong for a compliance user.

### Data model (migration `0004_relations.sql`)

```sql
CREATE TABLE IF NOT EXISTS doc_relations (
    from_doc_id  text NOT NULL REFERENCES documents(doc_id) ON DELETE CASCADE,
    to_doc_id    text NOT NULL,                          -- may reference a doc we haven't ingested
    relation     text NOT NULL CHECK (relation IN ('amends', 'repeals', 'consolidates')),
    effective_on date,
    evidence_chunk_id text,                              -- where the relation was stated
    PRIMARY KEY (from_doc_id, to_doc_id, relation)
);
ALTER TABLE documents ADD COLUMN IF NOT EXISTS in_force boolean NOT NULL DEFAULT true;
```

### Steps (TDD)

1. **Extractor (rules first, LLM second).** Write `ingest/relations.py`: regexes for RBI circular reference numbers (e.g. `RBI/2023-24/xx`, `DOR.xxx.REC.No.yy/…`) near verbs like *repealed / superseded / amended / निरस्त / संशोधित* ⚠️ (collect 20 real examples from your corpus *first* and make them the test fixtures). Only when rules fail, ask the LLM to extract `{to_ref, relation}` as JSON; store `evidence_chunk_id` so every relation is auditable.
2. **Resolver.** `in_force(doc) = not exists(relation in ('repeals','consolidates') pointing at doc)`. Recompute after each ingest. Unit-test with a small graph: A consolidates B and C; D amends A → B, C not in force; A and D in force.
3. **Retrieval filter.** Add `only_in_force: bool = True` to `search_docs` and the REST API; the SQL adds `JOIN documents d … WHERE d.in_force`. Keep the option to search everything (historians and auditors need it).
4. **Answer annotation.** If a cited document is amended by a later one in the corpus, the service appends a line: *"Note: amended by <title> (<date>) — check [chunk]"* (code, not the LLM).
5. **Eval.** Build 15 golden cases where the old and new rule differ; expected: the answer cites the in-force document. Report "in-force citation rate" before/after.

## Part B — Marathi

1. **Retrieval numbers.** Run the S2 harness on IndicQARetrieval `mr` 📚 for BM25 / dense / hybrid. Our tokenizer already handles Marathi (same Devanagari script, ✅ by construction); note that Marathi-specific characters like ळ are just letters to `\p{L}`.
2. **Language detection.** Script detection can't tell Hindi from Marathi (both Devanagari). Options, in order: (a) a UI language selector (simplest, most reliable); (b) a tiny heuristic on function words (Marathi आहे, आणि, च्या vs Hindi है, और, के) with tests; (c) a language-ID model. Do (a) + (b) and test (b) on 50 sentences from each language.
3. **Corpus slice.** 10–20 Maharashtra GRs relevant to the same themes from the Government of Maharashtra GR portal ⚠️ (verify URL, robots.txt and terms; many GRs are scanned or use legacy fonts, so your S1 OCR path with `mar+eng` gets a real workout: `tesseract --list-langs` must show `mar`).
4. **Refusal and answer language.** Add a Marathi refusal string and "write in Marathi" to `ANSWER_SYSTEM`; bump `PROMPT_VERSION`; re-record cassettes.
5. **Golden cases.** 10 Marathi questions (answerable + out-of-corpus).
